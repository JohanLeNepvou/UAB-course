PART 2 / 802–04 MIN

Use a lesson from top to bottom

Read the model before changing the code. Finish by explaining the result.

  1. Read: identify states, parameters, units, and initial conditions.
  2. Predict: sketch the direction of change or calculate a limiting result.
  3. Implement: edit the TODO and select Run Python.
  4. Verify: select Run & check; read a failing assertion as feedback.
  5. Interpret: write the requested engineering explanation and save your work.

A green check tests the code. The written deliverable tests your reasoning.

Teacher script

Open a lesson and locate the theory, task, editor, output, hint, solution, and hand-in requirement. Starter exercises are intentionally incomplete, so an initial failed check is expected. Run Python executes the code; Run & check executes the same code and then its assertions. Passing checks marks the lesson complete; students can also mark it manually. Neither action submits work to a teacher. Agree on your institution’s submission route before the course. Encourage students to predict, try, use a hint, and only then inspect a solution.

PART 3 / 804–07 MIN

Live demo: a derivative is not the next state

The first ODE is dy/dt = y with y(0) = 1. We know the answer before running Python.

dy/dt = y   →   y(t) = exp(t)   →   y(1) ≈ 2.718282
def rhs(t, y):
    return [y[0]]

sol = solve_ivp(rhs, (0, 1), [1.], rtol=1e-8, atol=1e-10)
assert sol.success
assert np.isclose(sol.y[0, -1], np.e, rtol=1e-6)

sol.y[0] is the first state's trajectory. The function returns its derivative.

Teacher script

Use the prepared first-ODE tab. Run the starter, whose derivative is zero, and show that a solver can finish successfully while solving the wrong equation. Run & check should fail. Replace the derivative with [y[0]], then rerun and compare the numerical and exact trajectories. Explain that the derivative function receives the current state from the solver. It does not manually advance time. The checks compare the answer with exp(t); sol.success alone cannot establish that the intended equation was implemented. The slide snippet assumes the NumPy and solve_ivp imports already present in the exercise.

Demonstrate

Run the wrong derivative, inspect the failed assertion, change one line, then rerun. Point to the analytical comparison and the terminal value.

Student checkpoint

Ask: “If sol.success is True, could the model still be wrong?” Expected answer: yes.

Run the first-ODE demonstration

PART 4 / 807–10 MIN

Check engineering structure, not only a plot

In the reversible reaction A ⇌ B, every loss from A is a gain to B.

dA/dt = −k₁A + k₂B
dB/dt = +k₁A − k₂B
d(A + B)/dt = 0
INITIAL CONDITION

A + B = 4 mol/L

A₀ = 3, B₀ = 1.

EQUILIBRIUM

Aeq = 8/3 mol/L

k₁ = 1, k₂ = 2 h⁻¹.

NUMERICS

Refine & compare

Check tolerances and conserved totals.

Teacher script

Add the two balances on the board: the reaction terms cancel. This gives a test independent of the numerical method. At equilibrium k1*A equals k2*B, and the total remains four. Students should later use this pattern for tank volumes and fed-batch amount balances. Distinguish verifying the implementation from validating biology against data. A conservation check can find a sign error but cannot prove that all chosen kinetic laws describe a real organism. Ask whether doubling both rate constants changes the equilibrium; it changes the speed, not the ratio.

Demonstrate

Show the coupled-reaction lesson and its conservation residual. Ask students to identify which derivative sign makes the total constant.

Student checkpoint

Students can explain why A+B is a stronger check than “the curves look reasonable.”

Open the coupled-reaction lesson

PART 6 / 814–16 MIN

Know what survives the next run

The course site starts each execution fresh. A notebook keeps variables until its kernel restarts.

This siteColab / Jupyter
Each execution uses a fresh namespace.Executed cells share the active kernel's variables.
Imports are included in each exercise.Run setup and imports before dependent cells.
Run & check reruns the edited code and tests.Run the edited exercise cell, then its check cell.
Stop / restart Python terminates the worker.Interrupt a running cell; rerun setup after a restart.

Teacher script

Demonstrate a notebook NameError by referring to a variable before running the cell that defines it. Cell position is not execution order: changing a parameter cell has no effect until it is rerun. After changing a derivative, rerun the solve and plot cells too. If a runtime restarts, recreate support files and rerun imports. Once a completed notebook is ready, restart its kernel and run it from top to bottom to check reproducibility. Do not start an incomplete student notebook with Run all: its first intentional assertion failure will interrupt the sequence.

Demonstrate

Change a parameter, rerun its definition, rerun the solve, then rerun the check. Explain why an old output may still show an old result.

Student checkpoint

Students can explain a NameError and know which cells to rerun after changing a parameter.
