PART 1 / 800–02 MIN

Python for process engineering

Three days of learning by doing.

Day 1

Start with Python

Write code and solve a simple ODE.

Day 2

Model a process

Build balances and add feedback control.

Day 3

Simulate fermentation

Explore feeding, growth, and ethanol production.

Teacher script

Welcome students and explain that previous programming experience is helpful but not required. The course builds from short Python functions to engineering balances and the original yeast fermentation model. By the end, students should be able to formulate a basic ODE, solve it with SciPy, and explain how they checked their answer. Keep this opening focused on what students will do rather than listing every numerical topic.

Demonstrate

Point out the three days in the sidebar. Ask who has used Python before.

Teacher script

Open one lesson and show only the model, exercise editor, and output. Run Python executes the edited code. Run & check executes that code and then checks the result. PART 3 / 804–07 MIN

Let’s run a little Python

Type a calculation. Run it. See what changes.

import numpy as np

length = np.sqrt(4.32**2 + 3.51**2)
print(length)

Change one number and run it again.

Teacher script

Use the hypotenuse example from the original Day 1 notebook. Explain import as loading a toolbox, ** as raising a number to a power, and print as displaying a result. This small standalone example can be entered in the site editor and executed with Run Python. Its result is about 5.56619. Change one input and ask students to predict whether the length increases. Return to the full exercise starter before asking students to use its lesson checks.

Demonstrate

Run the calculation, change 4.32 to a larger value, and rerun. Point to the changed output.

Student checkpoint

Students see the connection between editing code, running it, and updating output.

Try it in the editor

PART 4 / 807–10 MIN

From a calculation to a model

An ODE describes how a quantity changes over time.

dy/dt = y     y(0) = 1
def model(t, y):
    return [y[0]]

We can check the answer: y(1) ≈ 2.71828.

Teacher script

Introduce an ordinary differential equation in plain language: it gives a rate of change, and an initial condition tells us where to begin. The function returns the derivative; the numerical solver handles the time steps. Open the first ODE lesson and replace the starter’s zero derivative with y[0]. Show the plot and the comparison with exp(t). Mention that this known answer is one way to check a calculation. Leave solver internals, coupled reactions, and convergence for the lessons.

Demonstrate

Run the first ODE example and show its numerical and exact curves.

Student checkpoint

Students can distinguish the starting value from the rate of change.

See the first ODE

PART 5 / 810–14 MIN

Open your notebook in Colab

No local Python installation is needed.

  1. Open the Day 1 student notebook.
  2. Choose File → Save a copy in Drive.
  3. Click Connect, then run the first setup cell.

Give your copy a name, such as UAB_Day1_YourName.

Teacher script

Students should be signed in to Google before the presentation. Open the direct course notebook link and demonstrate saving a personal copy, renaming it, and connecting to a runtime. A normal CPU runtime is sufficient. The first setup cell contains the helper model files; students do not need to clone a repository or mount Drive. If a student cannot access Colab, let them continue using the site and resolve the account issue later.

Demonstrate

Save a named copy, connect, and run the setup cell. Keep the course page open in another tab.

Student checkpoint

Students have a personal notebook and can execute a cell.

Open Day 1 in Colab

PART 6 / 814–16 MIN

Run notebook cells in order

Select a code cell and press Shift + Enter.

1Setup & imports
↓
2Your exercise
↓
3Check & plot

Changed a value? Rerun that cell and the cells that use it.

Teacher script

Explain that a notebook remembers variables from executed cells until its runtime or kernel restarts. Cell position alone does not determine execution order. Demonstrate changing a parameter and rerunning both the parameter cell and the calculation. After a runtime restart, rerun setup and imports first. The website is different: each exercise execution is independent and includes its own imports. Keep that distinction in the spoken explanation rather than putting an environment comparison table on the slide.

Demonstrate

Change a value in a notebook cell and rerun the cells that depend on it.

Student checkpoint

Students know to rerun the calculation after changing an input.

PART 7 / 816–18 MIN

Save your work

Keep your code and the results you want to use.

  • In Colab: save your notebook in Drive.
  • On this site: use Course files → Export work.
  • For results: download your CSV files and plots.

The website and your Colab notebook are separate copies.

Teacher script

Show where to save the personal notebook and where the site exports a JSON backup. A JSON site backup restores site drafts; an .ipynb file is a notebook. Edited code does not synchronize between these environments. Generated CSVs live on the runtime and need their own download. Explain the actual submission route chosen by the teaching team, and ask students to include their written reasoning, labelled plots, and relevant data files.

Demonstrate

Show Export work in Course files and the notebook download option in Colab.

Student checkpoint

Students know where their work is saved.
